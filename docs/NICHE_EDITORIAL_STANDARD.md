# Niche Editorial Standard (Long-Tail SEO)

Use this as the default publishing standard for all new pages.

## Goal
Create pages that rank in low-competition, high-intent query pockets by being specific, practical, and difficult to replace.

## Core Rule
Do not publish generic rewrites.
Each page must solve one specific decision or failure case.

## Required Structure Per Page
1. One clear problem statement in the first paragraph.
2. One clear recommendation/answer (or clear "do not buy" outcome).
3. 3-5 concrete reasons tied to real use conditions.
4. Explicit disqualifier block (who should skip this).
5. At least 2 internal links to related pages.
6. At least 1 factual support point (spec, mechanism, failure behavior, or external source).

## Query Targeting Rules
- Target long-tail query patterns, not broad head terms.
- Use specific modifiers:
  - body/fit: `broad shoulders`, `sensitive skin`, `large thighs`
  - environment: `38F to 55F`, `indoor/outdoor transitions`, `daily commute`
  - failure mode: `fades after wash`, `plating wears off`, `leather cracks`
  - use-case: `first date`, `office`, `postpartum`, `walking all day`

## Metadata Rules
- Unique title per page, no duplicates.
- Description must summarize that exact page only.
- Include specific query language naturally (no keyword stuffing).

## Content Depth Rules
- Minimum depth should include mechanism, not just opinion.
  - Bad: "This is better quality."
  - Good: "This holds shape after repeated wash cycles because ..."
- Include tradeoffs explicitly.
- Include "why not the popular option" when relevant.

## Internal Linking Rules
Each editorial page must link to:
- Parent category page
- At least 2 adjacent editorials/notes
- 1 topic or utility page (comparison/how-to/glossary/use-case)

## Anti-Patterns (Do Not Publish)
- "Top 10" style filler pages
- Near-duplicate pages with only minor wording changes
- Thin pages with no mechanism or disqualifier
- Pages created only to include more affiliate links

## Update/Review Cadence
- Add `last reviewed` date for commercial pages.
- Refresh any page where product availability or fit assumptions changed.
- Update internal links when new related pages are added.

## Pre-Publish Checklist
- Is the page solving one specific query cluster?
- Is there a hard recommendation or hard exclusion?
- Is there a clear failure-mode explanation?
- Is there a disqualifier block?
- Are metadata/title unique?
- Are internal links present and relevant?
